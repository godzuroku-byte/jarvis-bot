# J.A.R.V.I.S. — исправленная сборка

Телеграм-бот на Python с Gemini, командами, обработкой медиа, админ-панелью и памятью.

## Что исправлено

- Заменена устаревшая модель Gemini 2.0 Flash на актуальную модель по умолчанию `gemini-3.8-flash`.
- Добавлен автоматический перебор резервных моделей, если выбранная модель недоступна.
- Вызовы Gemini переведены на асинхронный SDK, чтобы долгий запрос меньше блокировал Telegram-бота.
- Добавлены тайм-ауты и ограничение одновременных запросов.
- Ошибка больше не маскируется только общим сообщением: подробная безопасная диагностика доступна владельцу через `/diagnostics`.
- Временные файлы медиа удаляются даже при ошибке загрузки.
- Добавлены `/ping`, `/model`, `/diagnostics`.
- Улучшена обработка повреждённого `config.json` и экранирование динамического HTML в нескольких ответах.
- Существующие команды и обработчики оставлены.

## Требования

Python 3.11+ и переменные окружения:

- `BOT_TOKEN` — токен Telegram-бота.
- `GEMINI_API_KEY` — ключ Gemini API.
- `OWNER_ID` — ваш числовой Telegram ID.
- `GEMINI_MODEL` — необязательно, по умолчанию `gemini-3.8-flash`.
- `GEMINI_FALLBACK_MODELS` — необязательно, по умолчанию `gemini-3.7-flash,gemini-2.5-flash`.
- `GEMINI_TIMEOUT_SECONDS` — необязательно, по умолчанию 60 секунд.

Дополнительные сервисы (Cloudflare, Currents, Upstash) остаются необязательными для соответствующих функций.

**Никогда не добавляйте токены и API-ключи в код или публичный GitHub.** Задавайте их через Environment Variables в настройках хостинга.

## Команды для проверки

- `/ping` — проверить, отвечает ли бот.
- `/model` — посмотреть настройки модели (только владелец).
- `/diagnostics` — выполнить реальный тест Gemini и показать безопасную причину ошибки (только владелец).
- `/health` — системные показатели (только владелец).

Если `/diagnostics` показывает ошибку API-ключа, проверьте `GEMINI_API_KEY`. Если сообщает об ограничении запросов/квоте, проверьте квоту и доступ к API в Google AI Studio. Если ошибка относится к модели, попробуйте задать доступную вашей учётной записи модель в `GEMINI_MODEL`.

## Обновление существующего GitHub-репозитория

1. Скачайте ZIP этой сборки и распакуйте его на компьютере.
2. Откройте папку `jarvis-bot-main` внутри распакованного архива.
3. Откройте ваш репозиторий на GitHub и нажмите **Add file → Upload files**.
4. Перетащите файлы из папки `jarvis-bot-main` в окно GitHub. Не загружайте ZIP вместо исходных файлов.
5. Если GitHub спросит о совпадающих именах, подтвердите замену/загрузку новых версий.
6. Внизу страницы введите сообщение коммита, например `Fix Gemini integration and add diagnostics`, затем нажмите **Commit changes**.
7. Проверьте, что обновились `main.py`, `render.yaml`, `.gitignore`, `README.md`, а также `requirements.txt` остался в репозитории.
8. Если бот запущен на Render: откройте **Dashboard → ваш сервис → Environment** и проверьте `BOT_TOKEN`, `GEMINI_API_KEY`, `OWNER_ID`. В `GEMINI_MODEL` должно быть `gemini-3.8-flash` (или другая модель, к которой есть доступ). После коммита дождитесь нового deploy.
9. Откройте логи Render. Если бот запустился, напишите ему `/ping`, затем `/diagnostics`.

### Важно для Render

В `render.yaml` переменные `BOT_TOKEN`, `GEMINI_API_KEY` и `OWNER_ID` намеренно не содержат секретов и должны быть заданы в Dashboard вручную. Значение `OWNER_ID` теперь не зашито в репозиторий: укажите свой Telegram ID, иначе приложение не запустится.

Если на GitHub уже есть важные изменения, не заменяйте всё вслепую: сначала сохраните копию текущей версии или загрузите изменения в отдельную ветку и проверьте diff.
